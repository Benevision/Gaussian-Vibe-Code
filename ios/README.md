# SplatWork Capture (iOS)

SplatWork Capture is an iPhone app that records ARKit-posed image sequences, with LiDAR depth when the phone has it, for training Gaussian splats in **SplatWork** on the Mac. It writes the `.splatcapture` bundle described in `docs/PROTOCOL.md` §1 and sends it to the Mac over the local network as described in §5.

- **Requirements:** iPhone with an A12 chip or newer, running iOS 18 or later. LiDAR models (Pro iPhones from the 12 Pro on) also record depth and a fused point cloud.
- **Build tools:** Xcode 26 or later, plus [XcodeGen](https://github.com/yonaskolb/XcodeGen).

## 1. Setup

```bash
brew install xcodegen          # once
cd ios
xcodegen generate              # creates SplatCapture.xcodeproj from project.yml
open SplatCapture.xcodeproj
```

Run `xcodegen generate` again whenever you add or remove source files. Treat `project.yml` as the source of truth. A generated `SplatCapture.xcodeproj` is included, but any hand edits to it are overwritten the next time you generate.

Layout:

```
ios/
  project.yml                 XcodeGen spec (bundle id, Info.plist keys, build settings)
  SplatCapture/
    App/        app entry, settings model (persisted in UserDefaults)
    Capture/    ARSession engine, keyframe selector + blur gate, frame writer, LiDAR point fusion, manifest
    Library/    capture store on disk + library model
    Transfer/   Bonjour browser (_splatcapture._tcp), endpoint resolver, uploader, zip writer (zip64)
    UI/         capture screen, coverage overlay, mini-map, library, send-to-Mac, settings
    Resources/  Info.plist (generated by XcodeGen), asset catalog, app icon
```

## 2. Signing and running on your iPhone

1. In Xcode, select the **SplatCapture** target, then **Signing & Capabilities**.
2. Tick **Automatically manage signing** and choose your **Team**. You can instead set `DEVELOPMENT_TEAM` in `project.yml` and regenerate.
3. Change the bundle identifier from `com.example.splatcapture` to one you own, such as `com.yourname.splatcapture`. Change it in `project.yml` too so it survives regeneration.
4. Connect the iPhone, select it as the run destination, and press **Run** (⌘R). The first time, enable **Developer Mode** on the phone (Settings › Privacy & Security › Developer Mode).
5. Allow **Camera** when asked. Also allow **Local Network**: it is requested the first time you open "Send to Mac".

The app compiles for the Simulator, but ARKit world tracking does not run there. All real testing has to happen on a device.

## 3. Shipping to TestFlight

1. Create the app record. In [App Store Connect](https://appstoreconnect.apple.com), go to **Apps › + › New App**, choose platform iOS, and enter a name such as "SplatWork Capture". Pick the bundle ID you set above; if it isn't listed, register it under Certificates, Identifiers & Profiles › Identifiers. Enter any SKU.
2. Bump the version. Each upload needs a unique build number: raise `CURRENT_PROJECT_VERSION` in `project.yml`, or set **Build** under target › General. Change `MARKETING_VERSION` for user-visible versions.
3. Archive. Set the run destination to **Any iOS Device (arm64)**, then choose **Product › Archive**.
4. Upload. When the Organizer opens, select the archive and choose **Distribute App › App Store Connect › Upload**. Keep the defaults (automatic signing, upload symbols).
   - `ITSAppUsesNonExemptEncryption = NO` is already set, so you won't be asked about export compliance.
5. Wait for processing, which usually takes 5–30 minutes. The build then appears under **TestFlight** in App Store Connect.
6. Add internal testers. Go to **TestFlight › Internal Testing › +**, create a group, and add people from your App Store Connect team (up to 100). Internal builds need no Beta App Review. Testers install the **TestFlight** app from the App Store and accept the invite.
7. External testers (optional). Create an external group, add emails or a public link, and submit the build for Beta App Review. The first review takes about a day.

Command-line alternative, after setting a team:

```bash
xcodebuild -project SplatCapture.xcodeproj -scheme SplatCapture -configuration Release \
  -destination 'generic/platform=iOS' -archivePath build/SplatCapture.xcarchive archive
xcodebuild -exportArchive -archivePath build/SplatCapture.xcarchive \
  -exportOptionsPlist ExportOptions.plist -exportPath build/export   # method = app-store-connect
xcrun altool --upload-app -f build/export/SplatCapture.ipa -t ios --apiKey <KEY> --apiIssuer <ISSUER>
```

## 4. Using the app

1. Open the app and wait for the pill at the top left to say **Tracking** in green. Pan slowly side to side if it is still initialising.
2. Press the red **record** button.
3. Walk slowly around the subject. A haptic tick and a white flash mark each saved keyframe, and the coverage overlay fills in with the LiDAR points captured so far.
4. Press **stop**. The app writes the point cloud and manifest, then shows a summary.
5. Choose **Send to Mac**. Open SplatWork on the Mac and enable **Receive from iPhone**. The Mac appears automatically. Enter the 6-digit pairing code if SplatWork requires one, then press **Send**.
   - If the Mac doesn't appear, use **Enter address manually** and type the IP address and port shown in SplatWork.
   - You can also **Share as .zip** with AirDrop or Files. Captures also appear in the Files app under *On My iPhone › SplatWork › Captures*.

### Making a splat on the iPhone

**Make splat** (after a capture, or in the Library) turns a capture into a trained splat without any other computer:

1. **Prep on the phone.** The frames and ARKit poses become a training dataset (`CaptureImporter`, the same code SplatWork uses on the Mac), with the LiDAR point cloud as the starting splats. Optional **Masks** use Apple Vision on the phone: remove people, people and pets, or keep only the main object.
2. **Train** with the Metal trainer, sized to the memory iOS gives the app. **Quick** takes about 10–20 min on an iPhone 16 Pro Max. Keep the app open and the phone plugged in: iOS stops GPU work as soon as the app leaves the screen.
3. **View** the result (drag to orbit, two fingers to pan, pinch to zoom, double-tap to reset) or share the `.ply`. Splats are saved in *Files › On My iPhone › SplatWork › Splats*.

When other devices are on the network, tick them under **Train on**:
- **Macs** running SplatWork with *Compute › Act as a worker* on, **PCs** running SplatWork Worker, and **iPhones** with Compute on. One device trains the whole scene. Several devices split scenes of 400 or more photos into blocks that train in parallel and are merged on the phone.
- A **SplatWork Worker PC** also runs the steps that need Python: camera-pose refinement, learned moving-object masks (SAM 2) and sky masks with a learned skybox. Without one, these steps are skipped, which the result's *What happened* list shows.

Debug builds can run the whole flow without the UI, for example in the Simulator: `xcrun simctl launch <device> com.gunntower.splatcapture -splatSelfTest`. The options are documented in `Splat/SplatSelfTest.swift`.

### Tips for great captures

- **Move slowly and smoothly.** Motion blur is the biggest cause of poor splats. The app skips blurry frames and tells you to slow down when it does.
- **Use even, bright light.** Dim light means long exposures, which means blur. Avoid harsh shadows and changing light.
- **Exposure stays locked** while recording (default setting), so colours stay consistent. Start recording while pointing at a typical part of the scene, not at a window.
- **Orbit the subject.** Use two or three loops at different heights (low, eye level, high), pointing at the centre. Watch the ring around the mini-map: each green segment is a direction you've covered.
- **Overlap generously.** Every part of the scene should be seen from many angles. Fill in sparse regions of the coverage overlay.
- **Avoid moving things.** People, pets, and screens all cause ghosts. Mirrors, glass and shiny surfaces are hard for any method.
- **LiDAR works best between 0.3 and 4 m.** Don't get closer than about 25 cm; the app will warn you.
- **How many frames:** 150–400 keyframes is typical for an object or small room. 1920×1440 is the sweet spot. Turn on 4K or high-resolution stills only when you need fine detail; the captures get much larger.

## 5. What gets recorded

The bundle follows PROTOCOL §1 exactly:

- `images/NNNNNN.jpg` (or `.heic`) holds the colour frames in the camera sensor's native landscape orientation. The pose and intrinsics refer to this orientation.
  - Intrinsics are always scaled to the saved image resolution.
  - High-resolution stills use the still's own camera intrinsics and pose.
- `depth/NNNNNN.bin` holds the LiDAR Z-depth as float16 little-endian, in metres, at 256×192.
- `confidence/NNNNNN.bin` holds the per-pixel uint8 confidence (0, 1 or 2).
- `points.ply` holds the voxel-downsampled point cloud: binary little-endian, `x y z` float plus `red green blue` uchar, in ARKit world coordinates.
- `thumbnail.jpg` is a small portrait preview.
- `manifest.json` describes the capture.
  - It is rewritten every 25 frames, so an interrupted capture is still usable.
  - It also carries the extra key `"source": "iphone"`, which readers ignore.

Zips are written with the STORE method, with the bundle folder as the single top-level entry. Zip64 is used automatically for files or archives over 4 GB and for more than 65,535 entries. Making a zip temporarily needs free space roughly equal to the capture's size. The temporary file is deleted after sending or sharing.

## 6. Known limitations

- In high-resolution-still mode, ARKit may not attach depth to the still frame. In that case the app uses depth from the video frame that triggered the still, a few milliseconds earlier, together with that frame's pose for point fusion.
- Uploads run in the foreground. iOS gives the app about 30 seconds after you leave it, so keep the app open while sending.
- The coverage overlay uses SceneKit (`ARSCNView`). SceneKit is soft-deprecated, but it is fully functional on iOS 18–27.
